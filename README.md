# timetable_bmstu
Готовое решения для вашего расписание КФ МГТУ

## Разворот проекта

* Клонировать репозиторий
    ```bash
    git clone https://github.com/VlaDMaV/timetable_bmstu.git
    ```

## Деплой проекта

* Создать .env файл (можно полностью скопировать .env.example и заменить внутри данныке на свои)

* Запуск проекта
    ```bash
    docker-compose up --build -d
    ```
    
P.S. для просмотра логов контейнеров можно использовать:
```bash
    docker logs <container_id>
```

## Веб-админка

После запуска админка доступна по адресу
`http://IP_СЕРВЕРА:5555/<ADMIN_URL_SECRET>/admin/`. Секретная часть адреса,
логин и пароль задаются через `ADMIN_URL_SECRET`, `ADMIN_USERNAME` и
`ADMIN_PASSWORD` в `.env`. `ADMIN_URL_SECRET` и `SECRET_KEY` должны содержать не
менее 32 символов. Старый путь `/admin/` не зарегистрирован и возвращает 404.

Порт админки публикуется на внешнем интерфейсе через
`ADMIN_BIND_ADDRESS=0.0.0.0`. Для рабочего сервера рекомендуется поставить перед
ним HTTPS reverse proxy и включить `ADMIN_COOKIE_SECURE=true`, поскольку простой
HTTP не шифрует логин, пароль и сессию.

Админка поддерживает единый поиск по группам, преподавателям, предметам,
аудиториям, пользователям и занятиям. Для каждого справочника также доступны
локальные поиск, сортировка и фильтры.

В разделе **Системные → Календарь выходных** можно переключать месяцы и нажатием
на дату отметить или снять выходной. Выходные хранятся как конкретные календарные
даты и выделяются красным. В такие дни утренняя рассылка не отправляется, а в
просмотре расписания на сегодня, завтра, текущую и следующую неделю бот выводит
`🎉 Выходной` вместо занятий.

Подписанный пользователь может открыть **Настройки → Время оповещения** и выбрать:

- за час до первой пары своей группы;
- заданное время в день занятий;
- заданное время накануне занятий.

Время вводится строго в формате `ЧЧ:ММ`. Планировщик проверяет индивидуальные
настройки каждые 30 секунд, учитывает группу, числитель/знаменатель и календарь
выходных. Если на целевую дату у группы нет занятий, сообщение не отправляется.
Дату обработанной рассылки планировщик сохраняет для защиты от повторной проверки
и отправки.

В Telegram-группе подписку, учебную группу и время оповещения может менять
только пользователь, добавивший бота. Остальные участники получают сообщение:
«Менять настройки может только тот, кто добавил бота в группу».
Право сохраняется по Telegram ID и не зависит от последующей смены username.
Время в группе нужно вводить ответом на сообщение бота.

Миграция `c42d91e7a650` переносит прежнюю привязку по сохранённому username,
если найден ровно один соответствующий личный пользователь, либо по сохранённому
значению `user_<Telegram ID>`. Если владельца нельзя однозначно восстановить,
настройки остаются закрыты: администратор должен проверить и заполнить
`users.settings_owner_tg_id` для этого чата. Новый `/start` не присваивает права.
При новом добавлении бота владелец определяется из события Telegram.

При обновлении существующей установки примените миграцию перед перезапуском
сервисов (одного `create_all` для добавления столбца недостаточно):

```bash
docker compose run --rm --no-deps backend alembic upgrade head
docker compose restart backend bot admin schedule-monitor
```

Кнопка **Настройки → Идеи и предложения** принимает одно текстовое сообщение и
пересылает его пользователю с `ADMIN_ID`. В сообщении администратору указываются
имя, username, Telegram ID и кликабельная ссылка на профиль автора. Кнопка
**Ответить** под сообщением позволяет отправить автору текстовый ответ от имени
бота; она работает только для `ADMIN_ID`.

Тип семестра задаётся одной переменной в `.env`:

```dotenv
# Нечётный семестр: номер учебной недели -35 и совпадение чётности
SEMESTER_IS_ODD=true
```

При переходе на чётный семестр замените значение на `false`. Тогда бот везде
автоматически использует смещение `-6` и противоположную чётность. После изменения
перезапустите контейнер бота.

## Еженедельный мониторинг расписаний

Сервис `schedule-monitor` отдельно от backend и Telegram-бота проверяет публичное
расписание кафедр ИУК и МК Калужского филиала. По умолчанию проверка запускается
по воскресеньям в 09:00 по московскому времени. Группы аспирантуры с суффиксом
`a` не проверяются.

Монитор ничего не записывает в основное расписание автоматически. Если найдены
изменения, администратор получает в Telegram:

- список изменившихся групп;
- текстовый файл с добавленными и удалёнными занятиями;
- инструкцию ответить списком групп, словом `все` или словом `отмена`.

При подтверждении расписания выбранных групп заменяются одной транзакцией. ID
существующих групп и связи пользователей с группами сохраняются. Пустой или
повреждённый ответ BMSTU не может очистить расписание.

Настройки в `.env`:

```dotenv
SCHEDULE_MONITOR_TIMEZONE=Europe/Moscow
SCHEDULE_MONITOR_HOUR=9
SCHEDULE_MONITOR_MINUTE=0
SCHEDULE_MONITOR_CONCURRENCY=3
SCHEDULE_MONITOR_TIMEOUT=20
SCHEDULE_MONITOR_ATTEMPTS=5
SCHEDULE_MONITOR_INCLUDE_ASPIRANTS=false
SCHEDULE_MONITOR_RUN_ON_START=false
```

Управление только монитором:

```bash
docker compose up -d --build schedule-monitor
docker compose logs -f schedule-monitor
docker compose restart schedule-monitor
docker compose stop schedule-monitor
```

Ручная проверка без Telegram и без изменений БД:

```bash
docker compose run --rm schedule-monitor python -m schedule_monitor.main --dry-run
```

Разовая настоящая проверка с отправкой отчёта администратору:

```bash
docker compose run --rm schedule-monitor python -m schedule_monitor.main --once
```

Административные действия в Telegram открываются командой:

```text
/admin
```

Команда доступна только пользователю с `ADMIN_ID`. Бот запрашивает пароль из
`ADMIN_PASSWORD`, удаляет сообщение с введённым паролем и после успешного входа
показывает отдельное меню. В нём доступны запуск проверки расписаний, рассылка
сообщения выбранным группам и общая рассылка всем личным пользователям, которые
запускали бота. Общая рассылка принимает Telegram HTML, сначала показывает
предпросмотр и требует подтверждения. После трёх неверных попыток вход отменяется,
а кнопка выхода завершает админ-сессию. Прямые команды `/check_schedule`,
`/broadcast` и `/broadcast_all` работают только внутри активной админ-сессии.
Команды `/admin_on` и `/admin_off` включают и выключают контейнер веб-админки.
После включения бот присылает `ADMIN_PUBLIC_URL` из `.env`. Те же действия доступны
кнопками в админ-меню; отдельный контроллер имеет доступ только к Compose-сервису
`admin`, сам Telegram-бот Docker socket не получает.

Бот только ставит запрос проверки в очередь. Саму проверку выполняет отдельный
`schedule-monitor`, после чего присылает обычный отчёт и ждёт ответ со списком
групп, словом `все` или `отмена`.
